# Debug report: Worker routing and restart recovery reliability

- **Symptom:** An exact Voice/Terra request could reject an advertised, verified, degraded-but-eligible Terra route as `no_healthy_candidate`. A pre-start retry of the same portfolio revision could be rejected as a control-plane migration instead of an idempotency conflict, and graceful daemon restarts failed ordinary active controlled executions that had no prepared provider handoff.
- **Root cause:** Routing applied the phrase-derived capability heuristic as a hard floor before evaluating an explicit model pin, then collapsed capability rejection into a health failure. Portfolio reservations did not persist versioned control-plane provenance or a canonical task digest, and migration validation ran before complete request equivalence. Restart recovery supported provider handoffs but had no global ingress drain, all-project checkpoint barrier, or ordinary execution continuity checkpoint.
- **Fix:** Explicit model pins now override inferred capability ranking while still honoring a caller-supplied hard floor, and route diagnostics preserve catalog, verification, health, and capability rejection separately. New reservations persist versioned provenance plus a normalized SHA-256 task digest; complete equivalence runs before migration, distinguishes current conflicts from genuine legacy records, and preserves structured pre-start failure details. Graceful shutdown now drains controlled ingress, preflights every active project atomically, persists canonical continuity checkpoints, and resumes with rotated fences; missing or corrupt checkpoints remain fail-closed as `recovery_required`.
- **Evidence:** The integrated routing, binding, orchestration, migration, and restart suites passed 238/238. The full repository test run passed 2715/2715. `git diff --check`, syntax checks for every modified server module and the new restart regression, and the repository's `var`/non-arrow style checks passed.
- **Regression tests:** Exact incident coverage verifies degraded Terra pin admission and explicit-floor mismatch diagnostics. Binding regressions cover exact replay, changed key/model/digest conflicts, genuine legacy migration, and structured pre-start failures. Restart regressions cover graceful and double restart, multi-project all-or-nothing barriers, corrupt checkpoints, activation failure, abrupt restart fail-closed behavior, and session/task/lease deduplication.
- **Related:** Abrupt or otherwise uncheckpointed daemon loss intentionally does not infer successful continuity from stale session records; it requires explicit recovery instead of risking duplicate work.
- **Status:** DONE — implementation and static/test verification are complete; live restart canaries are verified separately after the committed build is activated.
